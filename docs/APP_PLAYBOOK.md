# 「桌面角落看比賽」這類 App 的開發要點（Basesmall 經驗）

## 這類 App 要成立的兩個條件

1. **比賽本身要有「一格一格」的狀態**，瞄一眼就有資訊：棒球的球數、出局、壘包；美式足球的第幾檔、還差幾碼。連續的運動（足球）沒有球員位置時，畫面上沒什麼好畫。
2. **要有免費、合法、接近即時、夠細的資料源**。MLB 三樣都有（Stats API 公開，每一球有座標、球速、球種），所以 Basesmall 成立。

英雄聯盟的狀態偏連續（經濟、擊殺、塔、龍），**沒有選手在地圖上的位置**（維護者已確認）。要先想清楚「瞄一眼要看到什麼」，再看資料撐不撐得起來。

## 資料層

- **先探針，後設計**：每個候選資料源少量實際請求，記下欄位、延遲、取得方式、條款，再寫結論表（Basesmall `docs/DATA_SOURCE.md` 第 9 節、`docs/PROBE_REPORT.md`）。
- **條款跟技術一樣重要**：Basesmall 放棄日職、韓職，就是因為條款禁止自動蒐集，或要偽造來源才拿得到。非公開的介面也要註明「被容忍使用、非正式承諾」，隨時可能改。
- **標準化模型**：原始資料 → `GameState`（某一刻的狀態）＋ `GameEvent`（發生了什麼）。一步（`TimelineEntry`）＝依因果順序的事件＋事件之後的狀態。渲染、通知、音效只看模型。
- **所有數字都「算到畫面上那一刻」**：選手數據、陣容都跟著時間軸，重播才不會爆雷。
- **輪詢要有禮貌**：照伺服器要求的間隔（MLB 的 `metaData.wait`），一次只有一個請求，失敗指數退避加抖動，能抓差異就不要抓全部。
- **量延遲**：拿 App 畫面跟資料源並排比，實測過才說「接近即時」。
- **對官方數字驗收**：錄幾場比賽當夾具，轉換結果逐項對照官方賽後數據（Basesmall：24 場、選手成績 0 筆不符）。錄下來的原始資料不提交。

## 介面

- **尺寸分級**：視窗高度決定顯示多少（點 → 條 → 場 → 全），拉右下角切換。最小的一級要能縮成一顆小膠囊。
- **不打擾**：通知不搶焦點；音效預設關；一鍵隱藏所有視窗的熱鍵；低調模式（只剩一排沒有顏色的數字）。
- **每個功能都做成開關**，預設值合理。
- **狀態要讓人看得懂**：資料源暫時沒動靜時（棒球換投手熱身），要顯示原因（「換投中」），不然使用者會以為當掉。標籤要用一看就懂的字（「代看」沒人懂，後來改成「非主隊」）。
- **雙語從第一天開始**：所有字串放 i18n 檔。
- **設定檔**：每個欄位壞了就各自退回預設，不要因為一個錯字丟掉整份設定。

## 發布

- 授權：Apache-2.0 加 NOTICE（要求改作保留署名、換名字），附第三方授權清單。
- Windows：只裝給目前使用者的安裝檔＋免安裝 zip；沒有程式碼簽章時，說明怎麼過 SmartScreen。
- macOS：有 Apple Developer 帳號就簽章加公證。
- 草稿發布 → 實際下載驗證三平台 → 維護者按 Publish。
- App 內更新要在**第一個有人用的版本**之前就做好：沒有更新功能的版本，使用者只能手動升級一次。
- 介紹網站：靜態頁＋Cloudflare Worker；搜尋用的 sitemap、結構化資料、`llms.txt`；給宣傳文用的簡化下載頁（不放贊助連結、不給搜尋引擎收錄）。部署前跑版面檢查。

## 宣傳（實際結果，不是期望）

- **2026-10-13 的數字**：下載 418 次（Windows 364）、已安裝的 App 啟動 202 次、GitHub 17 顆星、0 個 issue。
- **有效的**：PTT（板主事先核准）、Threads。流量是一波一波的，發文就來、兩天就退。
- **沒效或被擋的**：
  - X、LinkedIn：帳號沒有追蹤者，零點擊。
  - HN：新帳號被限流；官方要求文字手寫、不能用 LLM 生成或潤飾。
  - Reddit：r/baseball 拒絕；r/MLB 只允許內容創作者，其他人只能貼每日閒聊串；r/SideProject 被全站過濾器擋；r/NYYankees 在生死戰比賽串貼連結被罵是機器人。新帳號、新網域的連結特別容易被擋。
  - awesome-tauri 已經不收 App。
- **教訓**：
  - 產品的價值綁著賽季，宣傳時機只在賽季中。
  - 先寄信給版主問，比直接發好。
  - 在球迷版要挑時機，不要在緊張關頭貼連結。
  - 不要對宣傳效果樂觀，沒有受眾就是零。
- **英雄聯盟的時機**：職業賽季有幾個高峰（各賽區的春夏季賽、MSI、世界賽），日期要另外查證。
