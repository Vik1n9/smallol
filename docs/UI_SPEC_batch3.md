【艾莉絲・操偶師】

「倒下」小條是測試用自訂設定,了解。第三批逐項定稿如下,每項分「定稿」「答覆」「驗收」。

## 1. 全域熱鍵

**定稿:**

| 動作 | 組合 | 說明 |
|---|---|---|
| 隱藏/顯示全部視窗 | `Ctrl+Alt+Shift+H` | 條、選開視窗、資料窗、通知視窗一起收起或放回 |
| 低調模式開/關 | `Ctrl+Alt+Shift+Q` | 見第 2 項 |

- **三個修飾鍵,不用 `Ctrl+Alt+L`。** `Ctrl+Alt+L` 是 IntelliJ 與 Android Studio 的「整理程式碼」,全域註冊會讓它在所有程式裡失效。Basesmall 同理,用了三個修飾鍵。
- **與 Basesmall 避開:** Basesmall 用 `B`(隱藏)與 `L`(低調),兩個 app 同時開時不會互搶。
- 預設開。設定頁「一般」可整組關閉。註冊失敗時,設定頁顯示「熱鍵被其他程式占用」,不彈窗,另一組照常註冊。不做自訂按鍵。
- 隱藏期間事件照常進歷史,不發通知、不響聲、列 B 不更新(視窗是隱藏的)。放回時不補發,也不重播。
- **恢復路徑是硬規則:** 隱藏前必須確認至少一條回來的路(系統匣圖示的「顯示」,或熱鍵已註冊成功)。兩者都沒有就不提供隱藏,否則使用者會找不回視窗。
- 每次啟動一律是「顯示」,隱藏狀態不存檔。

**答覆:**
- 暫停通知**不綁熱鍵**:暫停不是緊急動作,圖示列已有。需要緊急的場合是「老闆走過」(隱藏)與「開始分享螢幕」(低調),所以綁這兩組。
- 兩組夠。

**驗收:**
- 註冊成功:呼叫 plugin 的 `isRegistered`,兩組都回 true。
- 觸發:用開發參數 `--press=hide|lowkey` 呼叫與熱鍵相同的處理函式,檢查四種視窗的 `IsWindowVisible` 變化。**不用合成按鍵**,註冊失敗時合成的按鍵會打進執政官正在用的視窗。
- 註冊失敗:開一個輔助程式先用 `RegisterHotKey` 占用同一組合,啟動 app,設定頁出現占用提示,app 不崩潰,另一組仍可用。
- 設定頁關閉後:`isRegistered` 回 false。
- 無恢復路徑時隱藏被拒絕:用開發參數同時停用系統匣與熱鍵,確認隱藏動作不執行。

## 2. 低調模式

**定稿:沿用 Basesmall 已定案的定義:偽裝成不像體育資訊的細條,不是淡化。** 只淡不偽裝,旁人還是一眼看得出是比賽。

| 項目 | 規格 |
|---|---|
| 條 | 單列 **150×24**,次要文字色,**沒有隊色、沒有色點、沒有色條**。內容只有數字:比賽中 `6:16 · 29:16`(殺數與時間);BP 中只寫 `BP`;賽前寫開賽的 `hh:mm`;局間或結束寫 `—`。位置不動,左上角固定 |
| 通知 | 卡片、小條、音效全不發 |
| 視窗 | 小地圖、本局 BP、選手面板、資料窗、歷史、模式選單暫時收起,離開低調時照原本開關狀態還原 |
| 列 B 與歷史 | 照常記錄,只是看不到 |
| 離開 | 雙擊低調條、熱鍵 `Ctrl+Alt+Shift+Q`、系統匣、設定頁。滑鼠移過**不展開**。條上的提示框文字「雙擊恢復」,延遲 700ms 才出現 |
| 持久性 | 手動開的低調存檔,下次啟動仍是低調。自動進入的不存檔 |

（2026-10-18 修訂：提示延遲由系統決定，約半秒；文字含熱鍵「雙擊恢復 · Ctrl+Alt+Shift+Q」，熱鍵關閉或未註冊時只寫「雙擊恢復」；理由見 ACCEPT_BATCH3 §2。）

- 低調模式優先於暫停通知計時器。
- 縮放低調條時不要把 150 寫進使用者存的條寬度(`main.ts` 的 resize 監聽已有 `resizingTo` 防護,低調進出要走同一條)。

**答覆:**
- 「條淡到多少」:不淡,改偽裝。
- **自動結束時不補發摘要卡**,同意你的傾向。理由:剛離開簡報就連跳一張摘要,等於把剛壓下去的東西一次倒出來。列 B 停在最後一則,歷史都有。

**驗收:**
- **尺寸:** 截圖量視窗矩形,150×24 ± 1。
- **去色:** 對低調條截圖逐像素檢查,所有像素 R、G、B 三值差都在 12 以內(沒有彩色)。
- **通知:** 低調中重播一局,通知視窗事件數 0、卡片 0、小條 0、聲音呼叫 0,歷史照常增加。
- **視窗:** 先開三個選開視窗與資料窗,進低調後 `IsWindowVisible` 全為 false;離開後還原成原本的開關狀態、位置與尺寸。
- **離開:** 雙擊與熱鍵都能離開;離開後條的位置、寬度與進入前一致。
- **持久:** 手動開低調後重啟,仍是低調;自動進入的重啟後不是。

## 3. 卡片音效

**定稿:**
- 只給卡片,預設關。設定頁「通知」:一個開關、音量三段(小、中、大)。
- **重大與重要分音:**
  - 重要:單音。
  - 重大:兩音上行。

  卡片的用途是叫你「現在值不值得看」,聲音能在不看螢幕時就分出這兩種緊急程度。
- Web Audio 合成,不帶音檔。**起始值**(交驅動核,聽感由執政官驗):

  | 項目 | 值 |
  |---|---|
  | 波形 | triangle |
  | 重要 | 660 Hz,140ms |
  | 重大 | 660 Hz 90ms,接 880 Hz 120ms,兩音間重疊 20ms |
  | 起音 | 5ms |
  | 衰減 | 指數衰減 |
  | 峰值增益 | 小 0.06 / 中 0.12 / 大 0.20 |

- **在主視窗頁面播放,不在通知視窗。** 通知視窗無內容時是隱藏的,隱藏頁面的音訊與計時器會被節流(第二批你們抓到過的同類問題)。
- 暫停、低調、簡報模式自動低調、隱藏期間都不響。一個卡片一聲,一個 5 秒步驟的卡片本來就只有一張。

**驗收:**
- **自動:** 用 `OfflineAudioContext` 把重大與重要在三種音量下各渲染一次,檢查:總長 ≤250ms、峰值在 ±5% 以內符合上表增益、沒有削波(峰值 <0.5)、重大兩音的頻率比約 4:3。
- **靜音條件:** 暫停、低調、隱藏三種狀態各觸發一張卡片,聲音呼叫數為 0。
- **人聽:** 執政官試聽一次(設定頁加「試聽」鈕,同 Basesmall 作法)。

## 4. 點通知開轉播網址

**定稿:選提案的「卡片上加按鈕」,不是點卡片本身。** 另加兩處修訂。

- 設定頁「通知」新欄位「轉播網址」,使用者自填,不內建任何網址。只接受 `http`、`https`,拒絕帶帳號密碼的網址,長度 ≤2048。無效時欄位下方顯示原因,不存檔。空白時這功能整個不出現。
- **卡片:** 有網址時,右上角時間的位置在滑過時換成「▶ 看」(英文「▶ Watch」)。點它開網址並消除該卡。點卡片其他位置仍是消除。
  - **時間欄寬固定。** 有設網址時,卡片的時間欄固定 48px(兩種狀態都是),標題寬度不會因為滑過而重新省略。
- **小條不加。**
- **列 B 尾端的按鈕不做。** 改成在條的 hover 圖示列加第 8 個圖示「▶」(有設網址才出現),那裡本來就是動作按鈕的位置。
- **安全:** 新增 Rust 命令 `open_watch_url`,**不收網址參數**,只開已存的設定值,寫入設定與開啟時各驗證一次。前端(含通知頁)任何腳本都不能傳任意網址進去。
- 不自動開、不預先連線,只有使用者點了按鈕才開。

**答覆:**
- 小條不要:太窄,且小條是參與感級別,不是「值得切過去」級別。
- 列 B 不要:改放圖示列,理由同上。

**驗收:**
- **網址驗證:** 合法 https、合法 http、`ftp://`、`javascript:`、`file:`、帶帳號密碼、超長、空白,各一次。只有合法的存得進去,按鈕只在合法時出現。
- **開網址:** 開發參數 `--open-stub` 讓命令改成寫檔而不真的開瀏覽器。驗證:點按鈕 → 記錄的 URL 與設定值完全一致、只記錄一次、該卡消除;滑過不觸發;點卡片本體只消除不記錄。
- **版面:** 量卡片標題寬度,滑過與不滑過差 ≤1px。
- **無按鈕處:** 小條上沒有按鈕;沒設網址時卡片上沒有按鈕、圖示列沒有第 8 個圖示。
- **安全:** 呼叫 `open_watch_url` 的前端程式碼沒有任何網址參數。

## 5. 邊緣吸附

**定稿:**
- 對象:條、三個選開視窗、資料窗。通知視窗不吸附也不當吸附目標。
- 門檻 **12px**(邏輯像素,換成實體像素是 12 × 縮放)。
- **時機:放開後吸附,不是拖動中即時。** `startDragging()` 是作業系統的拖曳迴圈,拖動中呼叫 `setPosition` 會跟系統打架而抖動。即時吸附要攔 `WM_MOVING`,需要視窗子類別,又碰到 tao 事件迴圈(第一批出現過一次 `flush_paint_messages` 斷言),風險不值得。放開判定:`onMoved` 最後一次事件之後 150ms。程式自己造成的移動要忽略,避免迴圈。
- 吸附不做動畫:最多位移 12px,直接對齊。
- 吸附到:
  - 工作區四邊(避開工作列),貼齊,間距 0。
  - 本 app 其他可見視窗,兩種:**相鄰**(邊對邊,間距 6px,與通知堆疊間距一致)與**同邊對齊**(上對上、左對左等,間距 0)。
- 同一軸有多個候選時取距離最近的。
- 按住 **Alt** 放開時不吸附。
- 只吸附條所在的螢幕工作區,不吸附螢幕之間的共用邊。
- 歷史、模式選單展開中不吸附(視窗尺寸會變),收合後也不補吸附。
- 不吸附到別的應用程式的視窗。

**答覆:** 12px 合適,不調整。

**驗收:**
- **純函式單元測試**(輸入視窗矩形、其他視窗矩形、工作區、縮放;輸出最終矩形),涵蓋:
  - 距離 11px 吸、12px 吸、13px 不吸。
  - 縮放 100%、150%、200% 的換算。
  - 相鄰間距 6、同邊間距 0。
  - Alt 按住不吸。
  - 候選取最近。
  - 展開中不吸。
  - 多螢幕只吸本螢幕工作區。
  - 隱藏與最小化視窗不當目標。
- **整合:** 開發參數 `--drag=<視窗>,<x>,<y>[,alt]` 呼叫與真實放開相同的處理,量最終位置,誤差 0。
- **實拖:** 執政官拖一次確認手感,這一項無法代操。

## 6. 簡報模式偵測

**定稿:**
- 每 **2 秒**查 `SHQueryUserNotificationState`(成本極低)。
- **觸發集合依模式而定,用使用者已宣告的模式當訊號:**

  | 模式 | 觸發低調的狀態 |
  |---|---|
  | 上班 | 忙碌(全螢幕)、D3D 全螢幕、簡報模式、勿擾時段、全螢幕商店 App |
  | 陪看 | 簡報模式、勿擾時段 |

  陪看模式下使用者自己全螢幕看轉播是預期行為,不該因此被壓掉;簡報與勿擾是他自己或作業系統明講的訊號,照樣尊重。「螢幕不在場」(螢幕保護、鎖定)不觸發。
- **進快、出慢:** 第一次查到觸發狀態就進入低調;連續 3 次(約 6 秒)都是「可通知」才離開,避免切視窗時閃爍。
- 只離開**自動進入**的那一次,不動使用者手動開的低調。
- 使用者在自動低調中手動離開時,在偵測狀態先回到「可通知」一次之前不再自動進入。
- 預設開,設定頁「一般」一個總開關,說明文字寫清楚「包含自己全螢幕看轉播時(上班模式)」。
- 只做 Windows。macOS 視為永遠「可通知」。

**答覆:** 全螢幕看轉播也低調:**上班模式接受**,陪看模式不低調。出錯的代價不對稱:簡報時彈出體育通知很尷尬,全螢幕看轉播時少了通知則無傷(他本來就在看)。

**驗收:**
- 用開發參數 `--notify-state=busy|d3d|presentation|quiet|ok` 覆蓋作業系統查詢結果,不需要真的開全螢幕。
- **上班模式:**
  - 前四個狀態各一次,2.5 秒內進入低調。
  - 之後設 `ok`,在第 3 次查詢(約 6 秒)後才離開,不是更早。
  - 設 `ok` 只 2 次就又回到觸發狀態,低調不離開(出慢)。
- **陪看模式:** `busy`、`d3d` 不進低調;`presentation`、`quiet` 進低調。
- **手動優先:** 自動進入後手動離開,同一個觸發狀態持續中不再進入;設一次 `ok` 後再設 `busy` 才再進入。手動開著時,偵測離開不動它。
- **總開關:** 關閉後任何狀態都不進入。
- **實測:** 執政官在 Windows 開一次「勿擾」,確認自動進低調(這一項要改系統設定,無法代操)。

## 動畫時序債(第三批結案前清)

**定稿:**
- 開發參數 `--anim-log=<檔>`,主視窗與通知視窗兩頁都用 capture 階段的 `animationstart`、`animationend`、`animationcancel` 監聽。
- 每筆記錄:頁面、動畫名稱、元素 class、`event.elapsedTime`、`performance.now()`、牆鐘毫秒。
- **節流判定:** 牆鐘上 end 與 start 的差,對上 CSS 標稱時長,差太多就是被節流。

**標稱值:**

| 動畫 | 標稱 ms |
|---|---|
| line-in | 200 |
| line-out | 120 |
| flash | 600 |
| glow | 1200 |
| bump | 120 |
| in-card | 220 |
| in-strip | 180 |
| out | 160 |
| fade(減少動態偏好) | 120 |

**驗收:**
- 8 倍速重播一局。
- 每筆牆鐘時長落在 [標稱 − 10, 標稱 + 60] ms 內。
- 沒有 `animationcancel`,除非該項目被取代。
- 覆蓋量至少:line-in ≥20、glow ≥3、bump ≥1(要有連推)、in-card ≥3、in-strip ≥10、out ≥10。
- 另外開一次減少動態偏好重跑,只檢查 fade。
- 逐筆的偏離與次數整理成表交我。
