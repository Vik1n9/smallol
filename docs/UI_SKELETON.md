# UI 骨架（2026-10-16）

Tauri 2 + TypeScript，骨架從 Basesmall 複製後刪減（沒有更新、熱鍵、風格檔、選配小視窗）。
資料只來自 Stream CV 服務的 `state.json`（合約：`DesktopLOL-StreamCV/docs/SERVICE_CONTRACT.md` v0）。

## 執行

```
npm install
npm run tauri dev          # App 視窗，讀 http://127.0.0.1:8787/state.json
npm run dev                # 只開網頁，瀏覽器看 http://localhost:1430/
npm test                   # vitest
npm run typecheck
```

檢查用參數（App 用 `--x`，瀏覽器用 `?x=1`；都不會寫入設定）：

| 參數 | 作用 |
| --- | --- |
| `sample` | 不問服務，直接畫樣本（只有開發版有樣本）：Stream CV 合約 v0.5 的真實輸出（StreamCV 88bc591），Day 2 KC vs MVK 第 2 局結束時，含塔、禁用、選手、三蟲、預示者 |
| `sample=draft` | 同一局 BP 進行到一半的真實狀態（藍方禁用 4 格、紅方 3 格） |
| `demo` | 搭配 `sample`：把已結束的樣本當成進行中，倒數會走 |
| `settings` | 開啟設定頁 |
| `pick=next` | 賽程視圖直接打開下一場的兩隊資料（截圖用） |
| `set=path:value,...` | 例：`set=language:en,show.gold:false,background:semi` |

開發版連不到服務時，會自動改畫樣本並標「樣本資料」；正式建置不含樣本（`dist/` 搜尋 game id 0 筆）。`fixtures/dev/series_draft_mock.json` 是假資料，只給測試用（禁用與 BP 順序支援之後的版面），App 不讀。

截圖：`npm run dev` 開著時跑 `node scripts/screenshots.mjs`，輸出到 `docs/screenshots/`。

## 模組

| 位置 | 內容 |
| --- | --- |
| `src/data/streamcv/contract.ts` | 合約的原始型別（全部 optional） |
| `src/data/streamcv/adapter.ts` | 原始 JSON → `MatchState`；壞欄位逐項丟掉，不會整份失敗 |
| `src/data/streamcv/source.ts` | 輪詢：5 秒一次、一次一個請求、`no-cache`、失敗退避 5→10→20→40→60 秒（±20%） |
| `src/model/types.ts`、`clock.ts` | 標準化模型；兩次更新之間時鐘繼續走（最多 20 秒，服務停了就看得出來） |
| `src/render/map-svg.ts` | 2.5D 塔圖（照 Basesmall 棋子的畫法：地面壓扁、有側面與陰影）。立著的塔是隊色柱子，倒下的是灰色殘座；水晶、主堡塔的重生倒數直接標在建築上 |
| `src/render/dragons.ts` | 龍屬性的顏色；畫面上是一格色塊加一個字（水、化…），不用 Riot 美術 |

| `src/data/champions.ts`、`items.ts`（與 `.json`） | 英雄與裝備的中英文名（只有文字，不用圖示；Data Dragon 16.20.1，`scripts/ddragon-names.mjs` 產生） |
| `src/settings/schema.ts` | 14 個顯示開關、3 個下方視圖開關（本局 BP、全場 BP、選手）＋語言、背景、經濟顯示方式、時鐘、資料來源網址 |
| `src/i18n/index.ts` | 繁中／英文，型別保證兩邊鍵相同 |

## 系列賽與 BP

由 Stream CV 服務提供（合約 v0.1「系列賽與 BP」，2026-10-16；提案見 `docs/CONTRACT_PROPOSAL.md`）。v0.1 的限制，畫面照實顯示：

- 選角依**位置**排（上、野、中、下、輔，每格前面標位置），不是選角順序：feed 只給位置。
- 禁用：v0.3（StreamCV 6e99ae1）起支援，依各隊的禁用順序（第 1–5 手）。不支援時寫「尚未支援」；支援但整局 5 格都空（服務沒看到該局 BP 畫面）時寫「這局沒有禁用資料」；BP 進行中的空格照畫空格。「輪到誰」仍未支援。
- 本局選角開局後才有；BP 進行中顯示「開局後才會有」。
- 服務沒在本局開始前看到系列賽時，勝場不知道，上方標籤顯示「MVK vs FUR」，滑鼠移上去看原因。
- 服務沒有系列賽資料時（例如沒有設定 API key），畫面寫「系列賽資料未接上」「還沒有 BP 資料」。

## 選手

位置、選手、英雄、等級、血量、K/D/A、補刀、金錢，加一行裝備名稱（可關；飾品、藥水不列）。BP 視圖不標位置，位置只在這裡（維護者 2026-10-16）。
由 Stream CV 服務提供（合約 v0.2「選手」）；`waiting` 時沒有，畫面寫「沒有選手資料」。details 取不到時裝備寫「裝備資料暫缺」。樣本的選手數據與隊伍總數對得上（測試：擊殺 22／8、金錢 59,398／46,224）。

## 轉播畫面物件（v0.4）

- 三蟲數：每隊一列寫「三蟲 n」（0 不寫）。開關：顯示項目的「三蟲數」。
- 預示者：上方野怪坑的下一隻是預示者時（`pitNext`），下一隻那列寫「預示者」加 15:00 倒數，15:00 後寫「可能在場」；這時巴龍倒數先不顯示。被打掉後，若服務從畫面公告看出是誰拿的（v0.5 `herald.team`），那一隊的列加「預示者」（滑鼠移上去看時間）；看不出來就不顯示。開關：「預示者」。
- 下一條龍屬性：服務讀轉播計時框；讀不到、改用規則推算時，色塊加虛線框，滑鼠移上去看原因。
- 藍紅方：BP 中官方資料的藍紅方常是反的。服務用畫面判斷；判斷不出來（`sidesSource: api_unconfirmed`）時，上方標籤和本局 BP 標「藍紅待確認」。
- 最初的需求說「不做三蟲／預示者」，理由是服務不支援；v0.4 起服務支援了，所以加上，兩者都可關。

樣本：`fixtures/streamcv/` 有三份，都是服務的真實輸出。`state_v03_mvk_fur_g3.json`（StreamCV aee7c8b）是既有測試用的；`state_v05_kc_mvk_g2.json`（88bc591，v0.5，含預示者歸屬）、`state_v04_kc_mvk_g2_waiting.json`（1f61ca1，BP 中）給新版的測試與開發模式用。

## 沒有比賽時：下一場與賽程（v0.6）

定位（維護者 2026-10-17）：小工具是「看比賽時旁邊那一格」；沒有比賽時才顯示賽程，做輕，不做成數據網站；不做歷史重播。

- `state.json` 是 `idle` 時，主畫面顯示**下一場**：兩隊代碼與全名、賽段、BO、開始時間（本機時區，含星期）、倒數。條狀與膠囊尺寸是一行。開關：顯示項目的「沒有比賽時：下一場與倒數」。
- 下方視圖**賽程**：最近兩場已結束的，加上之後所有場次；下一場以強調色標出；未定隊伍寫「待定」。
- **不爆雷**（預設開，存在設定檔）：賽程不顯示比分與勝方，已結束的只寫「已結束」。賽程視圖右上角可以直接切換「顯示比分／隱藏比分」，設定頁也有。比分只在 `/schedule.json` 的 `result` 裡，不爆雷時整個不讀。
- 賽程每 5 分鐘讀一次（服務自己快取 5 分鐘），網址由資料來源推出（同一個服務的 `schedule.json`）。
- 隊伍 logo（`teams[].image`）不用（CLAUDE.md 第 7 條）。
- **本屆歷史**（`/history/teams.json`、`/history/players.json`，每 3 分鐘讀一次；服務每局結束約 2 分鐘後重建）：
  - 本局 BP：每隊多兩行「常禁」「常選」，各取次數最多的 5 隻（×n）。開關：「本局 BP：本屆常禁／常選」。
  - 選手視圖：英雄名下有點狀底線時，滑鼠移上去看「本屆 這隻 n 場 · KDA」和他本屆所有英雄。
  - 賽程：點一場，看兩隊的本屆局數、常禁、常選，以及每位選手最常用的 3 隻（+n）；「← 賽程」回列表。未定隊伍寫「待定」。
  - 寫「本屆」「n 場」，不寫勝率 %：樣本很小（每隊 3–9 局，無懼選角下多半每隻 1 場），範圍只有本服務記錄的 Worlds 2026 小局。
  - 不爆雷（藏比分）時不顯示勝場；場數、KDA 照常顯示。`win`、`wins` 只在「顯示比分」時出現在滑鼠提示裡。
  - 樣本：`fixtures/streamcv/history_teams.json`、`history_players.json`、`history_game.json`（StreamCV 2ecdf40，服務的真實回應，2026-10-17 22:45 UTC，到 Day 3 共 19 局）。測試拿它們互相對帳：這一局的歷史＝即時樣本的 BP；單局回顧的最終數字＝即時樣本；Leaguepedia 的三蟲／預示者＝服務讀畫面的結果；每位選手的角色池場數＝在 teams.json 出現的局數。
  - 選手名一律去掉前後空白再比對（服務曾送出 `"C9 Loki "`；服務端已修，桌面工具這邊保留當第二道保險）。
- 賽程的測試資料是手寫的（照 2026-10-17 實際回應的形狀）；真實賽程是官方資料，不提交。
- **隊伍卡與選手卡**（`/teams.json`，合約 v0.7，每 30 分鐘讀一次）：做成滑鼠提示大小，不做資料頁（維護者：給一邊看比賽一邊開著的人）。
  - 隊伍代碼旁標種子（「LEC #3」）：本局 BP、選手視圖、下一場、賽程點開的那一場。滑鼠移到隊伍代碼上：全名、種子、晉級途徑、教練。
  - 選手名有點狀底線時，滑鼠移上去：服務給的 bio 一行（只由國籍、年齡、出道年、世界賽次數、冠軍數組成），加上本屆上場局數；替補標「替補」。
  - 賽程點開一場：兩隊各 5 位先發，加上國籍與年齡，以及本屆最常用的英雄。還沒上場的隊伍（例如主賽事隊伍）也列得出先發。
  - 本局 BP 視圖裡只有英雄、沒有選手名，所以選手卡只在選手視圖和賽程裡。
  - 樣本：`fixtures/streamcv/teams.json`（StreamCV 2ecdf40，和歷史樣本同一時間點，19 隊 97 人）。測試拿它和歷史樣本對帳：每位選手的本屆局數＝歷史樣本的局數，21 人全部一致。

## 從資料推論的地方（要知道的）

- **哪一路的水晶倒了**：合約只有「哪一隊、何時重生」，沒有路線。只有在「倒的水晶數＝水晶塔倒的路數」時才在地圖上標出路線，倒數標在那座水晶上（多座時依時間配對，是推定）；路線不能確定時，倒數以文字膠囊（「紅方水晶 2:40」）列在右邊。
- **未辨識的塔**：feed 的塔數比 CV 命名的多時，地圖該隊角落顯示 `+N?`。
- **主堡塔重生**：照合約的 `respawnAt`，時間到就畫回來（沒有等 `nexusRespawnsSeen` 確認）。
- **沒有 `towersLost`**：塔畫成半透明，表示「不知道」，不是「都還在」。
- 倒數只在 `in_game` 時顯示；`finished` 只畫最終狀態。
- 龍的中文名（火龍、水龍、土龍、風龍、海克斯龍、化學龍）是一般叫法，未對照官方中文版。

- 單元測試 107 項通過，含：樣本的「CV 命名的塔數＝對方 `towersDestroyedBy`＝tower 事件數」(10)；樣本三局 30 個英雄 ID 全部對得上名稱表、沒有重複（無懼選角）。

- 第一版用 Tauri debug 版實際開窗截過圖；2.5D 這一版只有瀏覽器截圖（`scripts/screenshots.mjs`），沒有另開 App 視窗截圖。
- **未驗證**：Tauri 正式建置（release、CSP 下對 127.0.0.1:8787 的請求）、進行中比賽的實際資料、延遲。
- 之後換 VPS 網址時，`src-tauri/tauri.conf.json` 的 CSP `connect-src` 要加上該網域，否則 App 內請求會被擋（瀏覽器開發模式不受影響）。
